# Verification backlog — what the docs say is unverified, and how to settle it

Every statement in `docs/` that calls itself unverified, unmeasured, inferred, a guess, or `Unknown`, with
whether it can be settled, by what instrument, and a probe design. Swept 2026-10-17. Probes follow the existing
pattern: a test in `LibRed.Core.AccessTests` / `LibRed.Engine.AccessTests`, `[Collection(AceCollection.Name)]`,
working on a `TemporaryDatabase.CopyPath` copy (never the fixture — ACE writes to anything it opens), logging what
ACE did through `ITestOutputHelper` while it is being measured, then moved into the existing class for its subject
as an assertion once known. Page-0 pokes go through
`DatabaseDefinitionPage.ReadMasked`/`WriteMasked` (internal, visible to both AccessTests projects).

Items marked ✔ were re-checked by reading the cited code/test; the rest are as the sweep reported them.

## 1. Affects what LibRed writes — probe first

LibRed writes its commit slot ([locking.md §6](format/locking.md)) in these cases on a choice, not a measurement:

| where | what LibRed does | probe |
|---|---|---|
| locking.md §6; page-00 §2.2 | **Slot 0 of an exclusive holder** follows the shared rule (`00 00` around two or more existing pages, counter + 1 closing every batch). Its values cannot be sampled while ACE holds the file; only the before/after values of a whole exclusive session can be read. | Before/after counts measured (locking.md §6): slot 0 is a counter that reads and an open/close leave, one `INSERT` raises by one, and `CREATE TABLE` + three `INSERT`s by five — one batch not accounted for. The mid-batch values need ACE's own writes traced (Frida on `NtWriteFile`, see the ACE I/O note). |
| page-00 §2.2 | **After `FF FF`** the counter goes on from `00 01` (256, a fresh file's start), never into `00 00`/`01 00`; an own slot found at `00 00` or `01 00` is counted on from `00 01` too. | Poke a slot to `FE FF`, run two single-statement writes through ACE as that user, read the slot. |
| locking.md §6 | **A page a batch leaves as committed is not written**, and a batch left with no page writes nothing, the slot included — for every publication, a commit's as well as a rollback's; a write outside a transaction that changes nothing takes no page lock. Measured only for failed statements (locking.md §6). ACE's write of an `UPDATE` that stores the values a row already holds is not measured. | `jetlockscenario`: `sql UPDATE T SET A = A`, read the slot before and 2 s after. |
| locking.md §6 | **A failed statement's batches** go out when it fails, not ~0.5–2 s later as ACE's do; when it both drew an AutoNumber and reserved a run of pages (a failed multi-row `INSERT … SELECT` into an AutoNumber table, say), the AutoNumbers go first and the global maps with the counting in the second batch — that combination is not measured. Where ACE's single batch carries only bytes of the undone change (a multi-row `UPDATE` refused with no page allocated), LibRed puts the pages back exactly and writes no batch: ACE's slot is one higher there. | The combination: an `INSERT … SELECT` into an AutoNumber table refused part-way after a run was reserved, slot read at return, 2 s later and after close. |
| locking.md §6 | **A failed publication** whose pages were all put back leaves the slot at its value before the batch (as if no batch ran); one whose pages could not all be put back leaves it as the batch left it — `00 00` after two or more existing pages. ACE's equivalent (a write refused mid-batch) is not measured. | Not reachable through ACE without a failing disk; leave unless a fault-injection harness appears. |

LibRed takes and honours ACE's page write locks, long-value read locks and table locks ([locking.md §4](format/locking.md)); these parts of it are chosen, not measured:

| where | what LibRed does | probe |
|---|---|---|
| locking.md §4 | **A statement that gets a page lock only after another user committed** reads the page again and is rolled back and run again — up to three runs, then 3218 — only when the page differs from the image the process held of it before the commit was noticed, or that image cannot be known (a page evicted since the statement began; inside a read-only scope). ACE reads the page again under the lock (measured) and is not known to re-run anything. What LibRed does not check: a page the statement read and does not write (an index page a uniqueness check read, say), which ACE does not check either as far as is measured. A re-run rolls back as though nothing ran: counters a failure keeps are taken back, an AutoNumber the abandoned run drew is not reissued — ACE, waiting rather than re-running, leaves no gap. | ACE `INSERT` into an AutoNumber table while another ACE user holds the data page, then read the counter. |
| locking.md §4 | **A table lock newly taken after another user committed** still re-runs the statement whatever changed (the design the plan used cannot be compared page by page: the catalog's parse may outlive the page's cache image). Under another user's steady stream of commits a statement that takes a table lock late — an `INSERT … SELECT`, a foreign key's parent — re-runs often. | None for parity; a design-generation check would narrow it. |
| locking.md §4 | **Page 0** is locked like any other page when LibRed writes it (a format-version raise). No ACE write of page 0 under a shared open has been seen. | DDL that raises the version (a `BIGINT` column on an ACE 12 file) under a shared ACE open, traced. |
| locking.md §4, §5 | **The TDEF page written early in an explicit transaction.** LibRed writes the AutoNumbers drawn and lets the page go as each statement returns, where ACE does about 500 ms after (a burst in one batch). It does so after any statement that left the page changed only in counters — measured for an `INSERT`, a failed `INSERT` and (holding nothing, writing nothing) a `DELETE`; a key-moving `UPDATE`, chosen. The complex id (`0x1C`) goes with the AutoNumber, chosen. Held to `COMMIT`: a page the transaction changed in more than counters (a design change), a catalog table's, one a rollback to an open savepoint would restore an image of — none measured. The index counts are added at `COMMIT` as the row count is (measured), but no other user's index-count change beside the open transaction was measured. **In one process** two connections stay optimistic: the second draws the id after the first's, as ACE's does, but its `INSERT` goes ahead and the later `COMMIT` is refused with a write conflict, where ACE refuses the second `INSERT` with 3218 at once (measured, `RollbackCounterProbeTest.Probe_ids_of_two_connections_when_one_rolls_back`). | The in-process refusal needs process-local page locks between connections — a design change, not a probe. A key-moving `UPDATE` and a `CREATE INDEX` inside a transaction beside a second ACE user's `INSERT`, through `jetlockscenario`. |
| locking.md §4, §5 | **The maps written early** are only those a statement changed by taking pages; a transaction that freed a page in the free map, or grew or converted the map, holds page 1 to `COMMIT`, as does one whose last statement failed until its next that succeeds. ACE writes a grown map's record early (measured); a `DELETE` of a chained memo inside a transaction writes no page 1, early or at `COMMIT` — the chain is held to close (measured, page-05 §9.1), as LibRed holds it; another freeing statement's early write is not measured. ## 3. Reserved / undecoded fields — one parameterised poke probe

Every other field was run 2026-10-18 (results in the settled table). Open: page types `0x0106`/`0x0107`, which
occur in no corpus file.

**Probe.** One DAO-built fixture (PK, secondary index, FK, memo, calculated column). Per field, a copy with a
distinctive pattern (`A5 5A …`, or the single bit for flags) in that field only. Each copy runs one ladder: ACE open
→ `SELECT *` → indexed seek → `INSERT` → `ALTER TABLE ADD COLUMN` (forces a TDEF rewrite) → `UPDATE` of a calculated
column's input (rewrites the envelope) → DAO `CompactDatabase`; re-read the bytes after each step. Classify:

- **rejected** — ACE validates it → writers must emit zero;
- **kept** — ignored → pass through verbatim (the faithful round-trip rule);
- **zeroed on rewrite/compact** — ACE regenerates it → zero is a valid write;
- **behaviour changes** (results, OLE DB `COLUMN_FLAGS`, DAO `Attributes`) → a meaning to document.
